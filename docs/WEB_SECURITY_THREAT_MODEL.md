## 1. Overview and effective resources

One operator on a Windows laptop processes authorized local videos using Streamlit and disposable Python workers. Future browser→FastAPI adds an HTTP authority boundary that does not exist as a product API today. Keep private media, DB, models and keys on the operator's account. External TTS is a conditional text transfer only, requiring explicit consent; local execution is the default. M5 package maintenance/build is a separate conditional workflow.

## 2. Threat model, trust boundaries and assumptions

Protected assets: original video/audio integrity; approved segment text/timestamps/revisions; current M2/M3/M4 artifact provenance; private SQLite/config/keys; downloaded-model integrity; filesystem outside managed roots; operator CPU/RAM/SSD; process ownership and stable Git/release history.

Actors: trusted operator; malicious website visited in the browser (can issue cross-origin requests but initially cannot read local sessions/files); attacker supplying a media file (controls its bytes/metadata/name, not executable paths); attacker controlling a remote model endpoint/redirect (bytes, not pinned trusted catalog); other unprivileged local programs. Same-account malware with direct read/write of private state already has comparable operator authority; session protection does not create an OS sandbox against it. No tenants/public users/LAN access are assumed. Public hosting needs a new threat model and access-control architecture.

Trust boundaries: browser origin→local API; upload bytes→native parser; request IDs→project/repository authority; worker→managed filesystem/SQLite; settings→executable/provider selection; network provider/model download→local state; private backup→restore destination; launcher status→process termination; developer source/dependencies→distribution. Authentication does not remove the need for file/record validation or native process resource bounds.

Invariants: no mutation without valid session+Origin+CSRF; no browser path/command authority; IDs scoped to their owning resource; source/earlier export never overwritten by processing failure; edits/reviews stay revisioned; failed/stale preview cannot authorize final render; only one heavy job; no cloud transfer or model installation by startup; keys stay backend-only; no automatic schema/data relocation. No unauthenticated storage mount. Browser disconnect does not cancel or erase a persisted job.

Assumptions/unknowns: operator controls trusted engine config/catalog/tool installation; local storage is local NTFS, not network SQLite/WAL. ACL inheritance, third-party browser extensions, clean-Windows packaging, all optional models and malicious-media parser exploits are NOT TESTED. Current logger formats messages but is not a universal redactor. Existing `.env`/snapshot storage is private but unencrypted. M5 tokenized Streamlit URL and health ownership are not a substitute for a FastAPI authenticated session. Current service path containment is useful evidence, not a proof against all reparse-point/TOCTOU cases.

### Implementation checklist and gates

W1: explicit127.0.0.1 bind and port ownership; strict Host and Origin; narrowly configured CORS; one-use bootstrap and session expiry; CSRF; safe error DTO; no DB bootstrap/model load/download; no frontend secret bundle; owned-process shutdown. Test both allowed browser flow and rejected raw/cross-origin variants. Origin/Host checks apply to health/preflight too, with health's deliberate no-session/no-user-data exception.

W2: streaming actual byte caps; validated FFprobe container/timeline; managed opaque assets/ranges; profile/path/reparse safeguards; safe metadata fields; source SHA preservation; no generic delete or arbitrary settings path. W3: atomic admission/idempotency, record membership/revisions, recovery/cancel ownership and WebSocket Origin/session/no-query-secret behavior. W4–W6: fixed compositor/mux options, review/rights/signature contracts, ASS escape/font whitelist, approved cloud consent, safe verified downloads/trash. W7: copied-profile migration/backup fault injection, real browser E2E, resource limits/negative tests and documented residual risks.

## 4. Severity calibration and open questions

- **Critical example:** an unauthenticated reachable local API chain allowing arbitrary executable execution triggered by a web page with no operator action. NOT demonstrated; intended loopback/session/strict input design counters this scenario. Normal operator-selected FFmpeg binary already has operator authority and is not itself new privilege escalation.
- **High example:** cross-origin read of private exports or path traversal overwriting outside managed roots, if auth/Origin/path controls are absent or bypassed. Requires an actual reachable endpoint and code path; neither is implemented in W0.
- **Medium example:** a bounded but repeatable authenticated operation bypasses the heavy slot and consumes SSD, or a copied-data migration has unsafe recovery. Depends on bounds, authorization and recoverability; a harmless malformed request rejected before side effects is not a finding.
- **Low example:** limited non-secret diagnostics reveal software versions to a local caller; public health should minimize this, but version disclosure is not credential compromise. Synthetic test traces or ordinary owner-visible local paths are not automatically vulnerabilities.

Open decisions: selected live profile and backup retention/ACL policy; future M5 integration and download licenses; exact dependency lock/patch policy; safe settings/profile selector UX; project archive schema; whether snapshot WS suffices (recommended); hardware measurement thresholds. No confirmed security defect is asserted by this document. The Web controls are acceptance gates awaiting implementation, not controls already proven effective.
