## Inspection and decision

Streamlit app/main.py loads settings, initializes additive SQLite schema and dashboard. Existing disposable AI/render workers invoke sys.executable -m app.worker/dub_worker/final_worker, cwd=ROOT. AI native packages deliberately isolated in subprocesses. Full freezing would turn sys.executable into a bootloader, breaking -m worker dispatch and dynamic Streamlit/Paddle resources. Choose a **one-folder distribution with a PyInstaller launcher plus managed external CPython3.11 runtime and pinned installed site-packages**, application code/Streamlit static resources copied explicitly, managed FFmpeg/FFprobe, external models. This is larger than a launcher-only executable but reliable/inspectable and avoids runtime pip/Python/FFmpeg setup for end users. No onefile extraction, Docker/Electron or installer at this milestone. Builder requires Windows and verified runtime/dependencies; model weights never bundled. Keep all third-party licenses/notices and dependency inventory. Actual redistributed runtime and native DLL behavior must be tested, not inferred from developer environment.

Reference: PyInstaller official usage/runtime-information docs describe one-folder builds and sys.executable becoming the bootloader. Sources: https://pyinstaller.org/en/stable/usage.html and https://pyinstaller.org/en/stable/runtime-information.html . Build tools pinned in requirements-build.txt; no change to verified application dependency stack except explicit M5 module support.

## Launcher / data / shutdown

Launcher resolves distribution relative to executable, never current directory. Uses bundled Python to run unchanged Streamlit/worker architecture; resets inherited Python/frozen-DLL runtime settings for child interpreter. Loopback only, dynamic free port, token-scoped URL, health readiness before browser. OS file lock per data root prevents duplicate launches; metadata validates owned process before reusing URL. Status/log/data/version displayed without env contents. Ctrl+C and --stop terminate only the launcher-owned server process tree; PID/create-time verification protects unrelated processes. Error state/log retained.

Default persistent root %LOCALAPPDATA%/FashionAILocalizer, separate from application code/version folders. User config.env and SQLite/models/projects/audio/exports/logs survive code upgrades/removal. Initialize only missing config/directories and additive DB migration; never copy a packaged database or overwrite existing data. Explicit data/models overrides support controlled tests. Backup via SQLite API plus source artifacts, restore only after stopping writers into a fresh destination; no silent data replacement. Cleanup limited to owned top-level temp files and leaves originals/M2/M3/exports/models intact. Uninstall portable code only; no user-data deletion by installer or launcher.
